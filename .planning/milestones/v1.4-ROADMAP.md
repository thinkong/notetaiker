## Overview

Improve editor flow with explicit creation, smarter navigation guards, and history integration. Users can now fluidly switch between capturing new thoughts ("Draft" mode) and refining historical ones ("Editing" mode) without risk of data loss or unnecessary friction.

## Milestone Summary

**Key Decisions:**

- **[15-01] Synchronized Note ID:** Used a synchronized state+ref pattern for `noteId` to balance React reactivity with debounced closure requirements.
- **[15-03] Header Badge:** Placed the Mode Badge in the header rather than the toolbar to make it a high-level context indicator.
- **[16-01] Data Router:** Migrated to `createBrowserRouter` to enable `useBlocker` support.
- **[16-02] Smart Dirty Check:** Implemented content-based comparison (current vs original) rather than a simple boolean "touched" flag to reduce false positives (e.g., undoing changes manually).

**Issues Resolved:**

- **UX Friction:** Users previously had no easy way to start a fresh note after editing one. `Cmd+N` and "New Note" button fixed this.
- **Data Safety:** Navigation guard now prevents accidental loss during app navigation (not just browser refresh).
- **False Positives:** Navigation guard no longer nags users if they revert their changes manually.

**Technical Debt Incurred:**

- **Phase 18 Docs:** `VERIFICATION.md` was skipped for Phase 18 (minor polish), verified via audit instead.
