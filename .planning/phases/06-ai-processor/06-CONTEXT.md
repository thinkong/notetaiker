# Phase 6: AI Processor - Context

**Gathered:** 2026-01-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Orchestrate background processing for newly created notes. New notes trigger a background processing job without blocking the UI. Processing status is tracked, and the worker handles failures and retries gracefully. Tag generation itself is Phase 7; this phase is the machinery.

</domain>

<decisions>
## Implementation Decisions

### Processing Visibility
- **Invisible (Magic):** No global or per-note status indicators (spinners, "processing...", etc.).
- **Real-time updates:** Tags appear immediately on the note card as soon as they are generated.
- **Silent failure:** No toasts or error alerts if processing fails; just drop it.
- **Visual Provenance:** Tags generated by AI should be visually distinct (e.g., different color) to distinguish them from manual tags, rather than using explicit text labels.

### Retry Behavior
- **Strategy:** Exponential backoff for transient errors.
- **Cap:** Stop retrying after 3-5 attempts to prevent infinite loops.
- **Offline handling:** Queue notes created offline and process them when connectivity returns.
- **Queue Priority:** Oldest failed notes first (catch up) rather than prioritizing new ones.

### Trigger Timing
- **Debounce:** Enqueue processing 10-30 seconds after the user stops typing.
- **Re-processing:** Edits to an existing note trigger re-processing and tag updates (replace old tags).
- **Minimum Content:** None — process everything, even single-word notes.

### Concurrency Strategy
- **Parallel Processing:** Use a worker pool to process multiple notes simultaneously.
- **Concurrency Limit:** Low concurrency (2-3 simultaneous jobs) to be conservative with API limits.
- **Rate Limiting:** If 429 errors occur, pause ALL processing for a backoff period (don't just throttle one).
- **Strict FIFO:** No special priority for the currently viewed note; strictly process in order of arrival/failure.

### Claude's Discretion
- Exact implementation of the job queue (e.g., in-memory vs persisted for this phase).
- Specific visual style for "AI tags" (color/badge design).
- Internal state management for the worker pool.

</decisions>
