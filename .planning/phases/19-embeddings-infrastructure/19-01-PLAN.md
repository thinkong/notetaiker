# Phase 19-01: Embeddings Foundation

## Goal

Initialize the vector database infrastructure and basic embedding service.

## Context

We need to store vector embeddings for notes to enable semantic similarity features. We will use `sqlite-vec` as a loadable extension for our existing `better-sqlite3` database.

## Changes

### 1. Dependencies

- **File:** `apps/api/package.json`
- **Action:** Add `sqlite-vec` dependency (v0.1.7-alpha.2 or compatible).
- **Action:** Run `pnpm install`.

### 2. Database Initialization

- **File:** `apps/api/src/services/indexer.service.ts`
- **Action:**
  - Update `initDb` to load the `sqlite-vec` extension.
  - Create `embeddings` table:
    - `id` (INTEGER PRIMARY KEY)
    - `note_id` (TEXT, Foreign Key)
    - `vector` (FLOAT[768]) (using sqlite-vec specific type/syntax)
    - `model` (TEXT)
    - `created_at` (DATETIME)
  - Create `embeddings_meta` table for change detection:
    - `note_id` (TEXT PRIMARY KEY)
    - `content_hash` (TEXT) - to skip re-embedding if content hasn't changed.

### 3. Embeddings Service

- **File:** `apps/api/src/services/embeddings.service.ts` (New)
- **Action:** Create class `EmbeddingsService`.
  - `storeEmbedding(noteId: string, vector: number[], contentHash: string)`
  - `getEmbedding(noteId: string)`
  - `findSimilar(vector: number[], limit: number)`
  - `deleteEmbedding(noteId: string)`

## Verification

- Test loading the extension in a standalone script.
- Verify table creation.
- Verify simple vector insertion and KNN search.
