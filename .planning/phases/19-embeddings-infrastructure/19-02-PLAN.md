# Phase 19-02: Async Embedding Pipeline

## Goal
Integrate embedding generation into the asynchronous job queue to ensure non-blocking saves.

## Context
Embedding generation is computationally expensive (even locally). It must happen in the background. We'll use the existing `p-queue` infrastructure.

## Changes

### 1. AI Service Update
- **File:** `apps/api/src/services/ai.service.ts`
- **Action:** Add `generateEmbedding(text: string)` method.
  - Use `ai-sdk` or direct Ollama fetch for `nomic-embed-text` model.
  - Return `number[]` (768 dimensions).

### 2. Queue Definition
- **File:** `apps/api/src/services/queue.service.ts`
- **Action:**
  - Add `embeddings` to `JobType`.
  - Define payload: `{ noteId: string, content: string }`.

### 3. Worker Implementation
- **File:** `apps/api/src/services/worker.service.ts`
- **Action:**
  - Add case for `embeddings` job.
  - Logic:
    1. Check `embeddings_meta` for `noteId`.
    2. Calculate hash of current content.
    3. If hash matches, skip (return).
    4. If different, call `aiService.generateEmbedding`.
    5. Call `embeddingsService.storeEmbedding`.

### 4. Storage Hook
- **File:** `apps/api/src/services/storage.service.ts`
- **Action:**
  - In `saveNote`, after writing file and updating metadata index...
  - Push `embeddings` job to queue.
  - Ensure this is non-blocking (fire and forget).

## Verification
- Save a note.
- Check logs for "Job embeddings processed".
- Check DB for new row in `embeddings` table.
- Edit note (small change) -> Check DB updates.
- Save note (no change) -> Check DB skips.
