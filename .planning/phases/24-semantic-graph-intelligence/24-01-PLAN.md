## Objective

Implement the backend clustering infrastructure for semantic graph intelligence. This plan creates a complete DBSCAN-based clustering system that computes topic clusters from note embeddings, supports soft clustering for nodes at boundary regions, and provides API endpoints for the frontend to consume.

**Purpose:** The backend needs to handle computationally expensive clustering (O(n²) with DBSCAN) so the frontend can focus on visualization. Pre-computation and caching ensure responsive UI even with large note collections.

**Output:** Fully functional cluster service with API routes, integrated into the existing service architecture.

Create a new utility file `apps/api/src/services/clusters.utils.ts` implementing:

1. **Cosine Similarity Functions** (required for DBSCAN distance metric):
   - `cosineSimilarity(a: number[], b: number[]): number` - Returns similarity score 0-1
   - `cosineDistance(a: number[], b: number[]): number` - Returns 1 - similarity (0 = identical)
2. **DBSCAN Algorithm** (custom implementation per research):
   - `dbscan(embeddings, epsilon, minPoints)` - Returns cluster labels and cluster groups
   - `regionQuery(embeddings, pointIdx, epsilon)` - Find neighbors within epsilon distance
   - Must use cosineDistance for distance calculations
3. **Adaptive Epsilon Selection**:
   - `estimateEpsilon(embeddings, k = 4)` - Use k-distance graph to find elbow point
   - Sort k-th nearest neighbor distances and use 15th percentile as epsilon
4. **Keyword Extraction for Cluster Labels**:
   - `extractKeywords(titles, maxKeywords = 3)` - Simple TF-IDF-like extraction
   - `generateClusterLabel(titles)` - Generate human-readable label from note titles
   - Use stopword list: "the", "a", "an", "and", "or", "but", "in", "on", "at", "to", "for", "of", "with", "by"

**Implementation notes from research:**

- DBSCAN should mark noise as -1, unvisited as -2 during processing
- Convert soft cluster assignment: use cosine similarity to cluster centroid as membership score
- For keyword extraction: tokenize (lowercase, remove punctuation), remove stopwords, calculate TF-IDF

**Do NOT use npm packages** for DBSCAN (custom implementation preferred per research). Cosine similarity can be hand-rolled (simple dot product).

1. **Constructor and Dependencies**:
   - Accept `db: Database` and `embeddingsService: EmbeddingsService` parameters
   - Store references for later use
2. **Cache Management**:
   - Private `cache: ClusterData | null = null`
   - Private `cacheVersion: number = 0`
   - Method `invalidateCache()` to clear cache when embeddings change
3. **Main API Method**:
   - `async getClusters(): Promise<ClusterData>` - Return cached data or compute new clusters
   - `async computeClusters(): Promise<ClusterData>` - Force re-computation
4. **Cluster Computation Pipeline**:
   a. Fetch all embeddings via embeddingsService (need to add method to fetch all)
   b. Estimate epsilon using k-distance graph (k=4)
   c. Run DBSCAN with minPoints=4 (per research recommendation)
   d. **Handle >8 clusters**: Merge smallest clusters into "Other" category
   e. **Calculate centroids** for each cluster (average of member vectors)
   f. **Calculate soft memberships** for all nodes to all clusters using similarity to centroids
   g. **Generate labels** from note titles in each cluster
5. **Data Structure**:

   ```typescript
   interface Cluster {
     id: number;
     label: string;
     color: string; // Placeholder - colors assigned client-side
     nodeIds: string[];
     centroid: number[];
   }

   interface NodeMembership {
     clusterId: number;
     weight: number; // 0-1 membership score
   }

   interface ClusterData {
     clusters: Cluster[];
     memberships: Map<string, NodeMembership[]>; // nodeId -> memberships (sorted by weight desc)
     noiseNodeIds: string[];
     computedAt: Date;
     version: number;
   }
   ```

6. **Soft Clustering Logic**:
   - For each node, calculate cosine similarity to each cluster centroid
   - Normalize similarities to 0-1 range based on epsilon
   - Keep top 3 memberships per node (for performance and visual clarity)
   - Nodes with no membership above threshold are noise

2. **Create API routes** in `apps/api/src/routes/clusters.ts`:

   ```typescript
   import { Hono } from "hono";
   import type { ClustersService } from "../services/clusters.service";

   type Variables = {
     clustersService: ClustersService;
   };

   export const clusters = new Hono<{ Variables: Variables }>()
     .get("/", async (c) => {
       const service = c.get("clustersService");
       const data = await service.getClusters();

       // Transform Map to plain object for JSON serialization
       return c.json({
         clusters: data.clusters.map((c) => ({
           id: c.id,
           label: c.label,
           nodeCount: c.nodeIds.length,
         })),
         nodeMemberships: Object.fromEntries(data.memberships),
         noiseNodeIds: data.noiseNodeIds,
         version: data.version,
         computedAt: data.computedAt.toISOString(),
       });
     })
     .post("/rebuild", async (c) => {
       const service = c.get("clustersService");
       await service.computeClusters();
       return c.json({ message: "Clusters rebuilt successfully" });
     });
   ```
